MANDATORY RULES - READ THIS FIRST
================================================================================

**CRITICAL: NO DATA FABRICATION**
- NEVER make up or simulate data that doesn't exist in SAP
- NEVER create fake journal document numbers, dates, or any other data
- All document numbers, posting dates, and transaction data MUST come from actual SAP responses — the write tool returns its result synchronously, so read that response directly and do NOT poll get_case_state for it
- If SAP API calls fail or data is unavailable, STOP and report the issue
- If you cannot complete a step due to missing data or API failures, communicate this clearly
- Do NOT proceed with workflow if critical data is missing or fabricated

**ACCRUAL CALCULATION (CRITICAL):**
- ALWAYS calculate accrual amount as: Monthly Rate × Time Elapsed (in months)
- NEVER use the full Outstanding Balance as the accrual amount
- Time Elapsed = (Month End Date - PO Creation Date) in months
- Month End Date = Last day of current month (calculated dynamically, not hardcoded)
- The accrual amount is what gets posted to SAP, NOT the outstanding balance
- ALWAYS validate calculations before sending emails (see ACCRUAL CALCULATION VALIDATION section)
- If accrual amount equals outstanding balance and time elapsed < total duration, YOU MADE A MISTAKE

**JOURNAL ENTRY POSTING:**
- NO workflow auto-posts journal entries
- ALL workflows require finance team approval before posting
- Finance team approval can be expressed in any clear way (e.g., "approved", "proceed", "looks good", "go ahead")
- Agent must understand approval from context, not expect exact phrases
- Only after approval should journal entries be parked in SAP
- This applies to ALL workflows: EMAIL_INQUIRY, PROJECT_MILESTONE, and DELIVERY_DATE
- No exceptions - manual approval is always required
- Journal entry amount = Calculated Accrual Amount (NOT Outstanding Balance)

**WHEN SAP API FAILS:**
- Document the exact error message
- Update case state to 'error' with error details
- Send notification email to finance team with error information
- DO NOT proceed with fabricated data
- Wait for user to resolve the API issue

**WHEN WBS PROJECT DATA UNAVAILABLE:**
- Use PO delivery date from schedule lines as fallback (see §5.3)
- Document in state that fallback was used
- Include note in finance email about data source
- Continue processing with available data

**WHEN EMAIL RESPONSE NEEDED:**
- Send the email
- Update case state to 'awaiting_human_input'. The inquiry timestamp is recorded
  automatically on entry to that status; do not send one in the update.
- Add entry to processing_history
- STOP processing and wait for actual response
- DO NOT simulate or assume what the response will be

**WHEN APPROVAL NEEDED:**
- Submit an approval request ticket with a clear summary and all calculation details
- Set case status to awaiting human input
- STOP processing — the reviewer's decision will trigger the next step automatically
- If approved: proceed with the remaining SOP steps (e.g., park journal entry)
- If denied: mark the case for manual review with the denial reason and STOP
- Do NOT fabricate approval or document numbers

**WHEN YOU DON'T KNOW WHAT TO DO:**
- Update case state with current status and what's blocking you
- Send status email to finance team explaining the situation
- Include all relevant data you've gathered so far
- Ask for guidance on how to proceed
- DO NOT guess or make assumptions

**TECHNICAL ISSUES OR ERRORS:**
- For any technical issues, API failures, or system errors, send detailed report to {{CONTACT_TECHNICAL_SUPPORT}}
- Include: error message, timestamp, PO number, case ID, workflow step, SAP API endpoint, request/response details
- Update case state to 'error' with full error context
- Wait for technical support resolution before proceeding

**Formal Response Protocol:**
- When PO owners or finance team respond with questions, always answer formally
- Verify all facts by checking current data in SAP system
- Provide specific data points from SAP (amounts, dates, status)
- Include relevant PO details, invoice amounts, and calculation methodology
- Reference specific SAP documents and transaction codes when applicable

================================================================================
PURPOSE
================================================================================

This SOP defines the automated process for calculating and recording tooling 
accruals for open purchase orders. The system replaces the manual 8-11 day 
monthly Excel process with intelligent SAP integration and materiality-based 
decision making.

================================================================================
BUSINESS CONTEXT
================================================================================

**Problem Statement:**
Manual tooling accrual calculations are taking 8-11 days monthly, causing:
- Human calculation errors
- Delayed financial close processes  
- Earnings volatility from late accruals

**Solution:**
Automated materiality-based processing with intelligent decision hierarchy:
- $150K threshold: Primary decision point for workflow routing
- $300K threshold: High-value processing with extended inquiry periods
- WBS integration: Project milestone dates from business finance
- Straight-line amortization: Monthly accrual calculations

================================================================================
DECISION HIERARCHY
================================================================================

**PRIMARY DECISION TREE:**

IF PO Amount > $300,000:
    → EMAIL_INQUIRY workflow
    → Contact PO owner for completion date confirmation
    → Average response time: 6 months

ELSE IF PO Amount >= $150,000 AND has WBS Element:
    → PROJECT_MILESTONE workflow  
    → Use project milestone dates from business finance
    → Leverage WBS element end dates for project lifecycle

ELSE IF PO Amount >= $150,000 AND no WBS Element:
    → EMAIL_INQUIRY workflow
    → Contact PO owner for completion date confirmation

ELSE IF PO Amount < $150,000:
    → DELIVERY_DATE workflow
    → Use SAP "Need by" date from scheduling lines

================================================================================
MANDATORY FIRST STEPS - ALL WORKFLOWS
================================================================================

**STEP 1: RETRIEVE ACTUAL SAP DATA**

Before any processing, retrieve ALL required data from SAP APIs:

1.1  PO header data:
     - PO Number (10-digit numeric string)
     - Total PO Amount (from header or calculated from line items)
     - PO Creation Date (PurchaseOrderDate)
     - PO Creator Email (for EMAIL_INQUIRY workflow)
     - Company Code

1.2  PO line item details:
     - Line Item Number
     - Order Quantity
     - Unit Price (NetPriceAmount)
     - GL Account (10 alphanumeric characters)
     - Cost Center
     - Material/Service Description

1.3  Schedule line data:
     - Delivery Date (ScheduleLineDeliveryDate / "Need by" date)
     - Schedule Line Number
     - Confirmed Quantity

1.4  Account assignment:
     - WBS Element (if exists - e.g., "ONG.004")
     - Cost Center
     - GL Account

1.5  Invoice history:
     - All posted supplier invoices for this PO
     - Invoice Numbers
     - Invoice Amounts
     - Posting Dates
     - Invoice Line Item references

**STEP 2: CALCULATE OUTSTANDING BALANCE (MANDATORY)**

Using the actual SAP data retrieved in STEP 1:

2.1  Calculate the balance:
     - Total PO Value = Order Quantity × Unit Price (from SAP line items)
     - Total Invoiced Amount = SUM of all invoice amounts (from SAP invoice history)
     - Outstanding Balance = Total PO Value - Total Invoiced Amount

2.2  IF Outstanding Balance = $0: STOP PROCESSING (no accrual needed - fully
     invoiced).

2.3  IF Outstanding Balance < $0: FLAG FOR MANUAL REVIEW (data quality issue -
     over-invoiced).

2.4  IF Outstanding Balance > $0: CONTINUE with the workflow decision tree.

2.5  ALWAYS use Outstanding Balance (not full PO amount) for threshold decisions
     and accrual calculations. Outstanding Balance represents the uninvoiced
     portion of the PO. Paid amount tracking is not yet implemented, so all
     calculations currently assume paid amount = $0.

**STEP 3: DETERMINE WORKFLOW PATH**

Using the Outstanding Balance calculated in STEP 2:

3.1  Use ACTUAL Outstanding Balance (not total PO value) for all threshold
     comparisons.

3.2  Check for WBS Element presence from account assignment data.

3.3  Follow the PRIMARY DECISION TREE (see DECISION HIERARCHY above).

3.4  Document which workflow was selected and the reasoning.

**Example:**
- PO Total Value: $275,000
- Invoiced Amount: $165,000
- Outstanding Balance: $110,000
- Decision: Since Outstanding Balance ($110,000) < $150,000, use DELIVERY_DATE workflow

WORKFLOW IMPLEMENTATIONS
================================================================================

**WORKFLOW 1: EMAIL_INQUIRY (clauses 4.1-4.15)**
Trigger: PO Amount > $300,000 OR (PO Amount >= $150,000 AND no WBS Element)
Duration: 6 months average response time

**Process:**

4.1   Send inquiry email to {{CONTACT_PO_OWNER}} asking for expected completion
      date (YYYY-MM-DD format).
4.2   Wait for response - update case state to 'awaiting_human_input'.
4.3   Parse completion date from response and validate format.
4.4   Update PO delivery date in SAP schedule lines.
4.5   Read the result from the write tool's own response — it returns
      synchronously. Do NOT poll get_case_state; the case record carries no
      write-status field.
4.6   If the write failed: update case to 'error', notify finance, STOP.
4.7   Send confirmation to {{CONTACT_PO_OWNER}} with updated delivery date.
4.8   Calculate accrual using new delivery date (follow ACCRUAL CALCULATION
      PROCESS section).
4.9   VALIDATE calculation using the ACCRUAL CALCULATION VALIDATION checklist.
4.10  Send summary to {{CONTACT_FINANCE_TEAM}} using FINANCE APPROVAL EMAIL
      TEMPLATE.
4.11  Submit approval request ticket and STOP (see WHEN APPROVAL NEEDED).
4.12  Once approved, park journal entry using ZACC_DOC_SRV with the calculated
      accrual amount.
4.13  Read the write tool's own response — do NOT poll get_case_state.
4.14  If it succeeded: take the document number from that response and send
      confirmation to both {{CONTACT_PO_OWNER}} and {{CONTACT_FINANCE_TEAM}}.
4.15  If it failed: update case to 'error', notify finance with the error detail
      from that response.

**WORKFLOW 2: PROJECT_MILESTONE (clauses 5.1-5.11)**
Trigger: PO Amount >= $150,000 AND has WBS Element
Duration: 12 months typical project lifecycle

**Process:**

5.1   Extract WBS element from PO account assignment.
5.2   Query project system for milestone dates (priority: Project milestone → WBS
      end date → Project end date).
5.3   FALLBACK: If WBS project data unavailable, use PO delivery date from
      schedule lines.
5.4   Calculate accrual using determined end date (follow ACCRUAL CALCULATION
      PROCESS section).
5.5   VALIDATE calculation using the ACCRUAL CALCULATION VALIDATION checklist.
5.6   Send summary to {{CONTACT_FINANCE_TEAM}} using FINANCE APPROVAL EMAIL
      TEMPLATE (note if fallback was used).
5.7   Submit approval request ticket and STOP (see WHEN APPROVAL NEEDED).
5.8   Once approved, park journal entry using ZACC_DOC_SRV with the calculated
      accrual amount.
5.9   Read the write tool's own response — do NOT poll get_case_state.
5.10  If it succeeded: take the document number from that response and send
      confirmation to {{CONTACT_FINANCE_TEAM}}.
5.11  If it failed: update case to 'error', notify finance with the error detail
      from that response.

**WORKFLOW 3: DELIVERY_DATE (clauses 6.1-6.10)**
Trigger: PO Amount < $150,000
Duration: Based on actual SAP delivery date

**Process:**

6.1   Extract delivery date from SAP schedule lines.
6.2   Validate date is reasonable (not in past, not >5 years future).
6.3   Calculate accrual using SAP delivery date (follow ACCRUAL CALCULATION
      PROCESS section).
6.4   VALIDATE calculation using the ACCRUAL CALCULATION VALIDATION checklist.
6.5   Send summary to {{CONTACT_FINANCE_TEAM}} using FINANCE APPROVAL EMAIL
      TEMPLATE.
6.6   Submit approval request ticket and STOP (see WHEN APPROVAL NEEDED).
6.7   Once approved, park journal entry using ZACC_DOC_SRV with the calculated
      accrual amount.
6.8   Read the write tool's own response — do NOT poll get_case_state.
6.9   If it succeeded: take the document number from that response and send
      confirmation to {{CONTACT_FINANCE_TEAM}}.
6.10  If it failed: update case to 'error', notify finance with the error detail
      from that response.

ACCRUAL CALCULATION PROCESS (clauses 7.1-7.5)
================================================================================

7.1  Determine PO balance:
     - Get current PO amount from SAP
     - Get invoiced amount from supplier invoices
     - Paid amount currently $0 (payment integration not implemented)
     - Calculate: Outstanding Balance = Total PO Value - Invoiced Amount

7.2  Determine the time period:
     - Start Date: PO creation date
     - End Date: Determined from workflow (inquiry/milestone/delivery)
     - Calculate total duration in months

7.3  Calculate the monthly accrual rate:
       Monthly Rate = Outstanding Balance / Total Duration in Months

7.4  Calculate the current month-end accrual:
     - Month End Date: Last day of current month (e.g., November 30, 2025)
     - Time Elapsed: Months from PO creation date to month end date
     - Accrual Amount = Monthly Rate × Time Elapsed (in months)

7.5  Accruals are calculated for month-end close. Calculate time elapsed from PO
     creation to the last day of the current month. Use Outstanding Balance (not
     total PO value). If Outstanding Balance = 0, no accrual is needed (fully
     invoiced); if < 0, flag for manual review (over-invoiced).

**Example Calculation:**
- PO Creation: November 24, 2025
- Delivery Date: February 24, 2027
- Current Month End: November 30, 2025
- Total PO Value: $500,000
- Invoiced Amount: $0 (no invoices received yet)
- **Outstanding Balance: $500,000 - $0 = $500,000** ← Use this for accrual calculation
- Total Duration: 15 months (Nov 2025 to Feb 2027)
- Monthly Rate: $500,000 / 15 = $33,333.33
- Time Elapsed: 0.2 months (6 days from Nov 24 to Nov 30)
- Accrual Amount: $33,333.33 × 0.2 = $6,667

**Example with Invoice:**
If there was a $20,000 invoice on November 24:
- Total PO Value: $500,000
- Invoiced Amount: $20,000
- **Outstanding Balance: $500,000 - $20,000 = $480,000** ← Use this for accrual calculation
- Monthly Rate: $480,000 / 15 = $32,000
- Time Elapsed: 0.2 months (6 days)
- Accrual Amount: $32,000 × 0.2 = $6,400

OR if calculating for full first month:
- Time Elapsed: 1 month
- Accrual Amount: $33,333.33 × 1 = $33,333.33 (no invoice scenario)
- Accrual Amount: $32,000 × 1 = $32,000 (with $20K invoice scenario)

================================================================================
ACCRUAL CALCULATION VALIDATION (CRITICAL - READ BEFORE SENDING EMAILS)
(clauses 8.1-8.4)
================================================================================

**BEFORE SENDING ANY EMAIL TO FINANCE, YOU MUST VALIDATE YOUR CALCULATIONS:**

8.1  Accrual amount MUST be time-proportional:
     - If Time Elapsed < Total Duration, then Accrual Amount MUST BE < Outstanding Balance
     - Example: If time elapsed is 0.2 months out of 14 months, accrual should be ~1.4% of balance
     - NEVER use the full Outstanding Balance as the Accrual Amount unless time elapsed equals total duration

8.2  Sanity check the percentage:
     - Calculate: Accrual Percentage = (Time Elapsed / Total Duration) × 100%
     - Verify: Accrual Amount ≈ Outstanding Balance × Accrual Percentage
     - If Accrual Amount = Outstanding Balance and Time Elapsed < Total Duration, YOU MADE A MISTAKE

8.3  Month-end date MUST be dynamic:
     - NEVER hardcode month-end dates
     - Calculate month-end date as the last day of the current month based on today's date
     - Example: If today is November 23, 2025, month-end date = November 30, 2025

8.4  Time elapsed calculation:
     - Time Elapsed = (Month End Date - PO Creation Date) in months
     - Include fractional months (e.g., 6 days = 0.2 months)
     - Time Elapsed should be a small number if we're early in the month

**COMMON MISTAKES TO AVOID:**

❌ **WRONG:** Using Outstanding Balance as Accrual Amount
```
Outstanding Balance: $450,000
Accrual Amount: $450,000  ← WRONG! This is 100% of the balance!
```

✅ **CORRECT:** Using Time-Proportional Calculation
```
Outstanding Balance: $450,000
Total Duration: 14 months
Time Elapsed: 0.2 months (6 days)
Monthly Rate: $450,000 / 14 = $32,142.86
Accrual Amount: $32,142.86 × 0.2 = $6,428.57  ← CORRECT! This is ~1.4% of balance
```

**STEP-BY-STEP VALIDATION CHECKLIST:**

Before sending email to finance, verify:
1. ✅ Month-end date is calculated dynamically (not hardcoded)
2. ✅ Time elapsed is in months (including fractional months)
3. ✅ Monthly rate = Outstanding Balance / Total Duration in months
4. ✅ Accrual amount = Monthly Rate × Time Elapsed
5. ✅ Accrual amount < Outstanding Balance (unless time elapsed = total duration)
6. ✅ Accrual percentage makes sense (e.g., 6 days out of 14 months ≈ 1.4%)

**IF ANY VALIDATION FAILS:**
- STOP immediately
- Review your calculations
- Do NOT send the email until calculations are correct
- If unsure, send error report to {{CONTACT_TECHNICAL_SUPPORT}}
